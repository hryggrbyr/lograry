The `404` error you're seeing in that URL reveals the issue: **the `site_id` is incorrect.**

In Netlify Identity/Auth, the `site_id` shouldn't be your GitHub URL (`hryggrbyr.github.io`); it must be the **API ID** (a UUID like `12345678-abcd-...`) or the specific **Netlify subdomain** (like `your-site-name.netlify.app`) assigned by Netlify.

### Why it works on your computer but not your phone

On your computer, you likely have a local cookie or an active session where the CMS has already cached the correct credentials. On your phone, you are starting a fresh "handshake." When the CMS sends that `hryggrbyr.github.io` string to Netlify, Netlify's API looks for a site with that internal ID, fails to find it, and returns a `404 Not Found`.

---

### How to Fix the 404

#### 1. Verify your `config.yml`

Check your `public/admin/config.yml` (or wherever your config lives). The `backend` section should look like this:

```yaml
backend:
  name: github
  repo: hryggrbyr/lograry # Your repo path
  branch: main
  site_domain: your-site-name.netlify.app # NOT your github.io address

```

#### 2. Check Netlify Identity Settings

1. Go to your **Netlify Dashboard**.
2. Select your site.
3. Go to **Site configuration** > **Site info**.
4. Look for **API ID**. If you are using a custom auth setup, you sometimes need to use this UUID.
5. Ensure **Identity** is enabled and **Git Gateway** is connected under "Services."

#### 3. Update the External Provider

If you are using GitHub as the external provider:

* Go to **Site configuration** > **Identity** > **Registration**.
* Under **External providers**, make sure GitHub is enabled.

### Summary of the URL Error

The URL you provided:
`https://api.netlify.com/auth?provider=github&site_id=hryggrbyr.github.io`

Should actually look like:
`https://api.netlify.com/auth?provider=github&site_id=xxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`
*(Where the x's are your Netlify API ID)*

### One last thing to check

Since you are using **Astro**, check if your `BASE_URL` logic in `admin.astro` is accidentally appending something strange when viewed on a mobile browser. Sometimes mobile browsers handle relative paths differently if there is a trailing slash missing in the URL.
