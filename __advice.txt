This specific **React Error #31** is occurring because of the "shim" you created for `React` in your `admin.astro` file.

### The Cause: The React Shim

In your script, you created a fallback `React` object to handle cases where `window.React` might be undefined.

* **What's happening:** When Decap CMS loads, it eventually provides a real version of React. However, your code is manually creating an object with `{ type, props, _isReactElement: true }`.


* **The Error:** Decap CMS's internal React engine encounters this "fake" element and doesn't know how to render it because it isn't a true React Fiber node. The error message explicitly mentions an `object with keys {type, props, _isReactElement}`—which matches your shim exactly.



---

### The Fix: Use the CMS Global React

You should not try to create your own `React.createElement` logic. Decap CMS exports the version of React it uses globally. You just need to ensure your templates wait for it to be ready.

Delete this section from your `admin.astro`:

```javascript
// DELETE THIS ENTIRE BLOCK
const React = window.React || {
  createElement: (type, props, ...children) => { ... },
  Fragment: Symbol.for("react.fragment"),
};

```

**Replace it with this safer initialization:**

```javascript
function registerPreviewTemplates() {
  // Use the React version provided by the CMS
  const h = window.React.createElement;

  CMS.registerPreviewTemplate("books", ({ entry, widgetFor }) => {
    const data = entry.getIn(["data"]).toJS();

    // Use 'h' (React.createElement) directly
    return h("div", { className: "my-custom-preview" },
      h("h1", null, data.title),
      h("article", { className: "prose" }, widgetFor("body"))
    );
  });
}

```

---

### Why the Preview shows HTML strings

If your preview is currently showing raw tags (like `<p>content</p>`) instead of formatted text, it is usually because of one of two things:

1.
**Missing `widgetFor`:** You must use `widgetFor('body')` instead of `data.body`. `widgetFor` converts the Markdown into real React components; using `data.body` just prints the raw text string.


2. **CSS Isolation:** Decap CMS previews are inside an `iframe`. If you don't register your styles, the HTML is there but it has no styling, making it look like unformatted text.



### How to fix the "String" issue

Ensure your template looks like this (which you already have partially implemented):

*
**Use `widgetFor("body")**` for the main content area.


*
**Inject your CSS** so the HTML elements (h1, p, etc.) actually look like a website:



```javascript
// In your initCMS function
cms.registerPreviewStyle(`${BASE_URL}admin/preview.css`);
